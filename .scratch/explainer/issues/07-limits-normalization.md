# 上限与归一化规则

Type: grilling

## Question

输入侧的统一规则：

- 选择文本上限：默认 500 词（常量置于 `explainer` 服务配置，集中一处便于未来升设置项），超限 toast + 截断为前 500 词，还是禁触发？——用户倾向"尽快实现但易拓展"，给最终结论。
- 文本归一化 → `textHash` 的精确规则：strip HTML/实体、空白与标点归一、大小写（保留还是丢弃）、全角/半角；CFI 一并存储与否。
- 空选择、全空白、只含符号的降级行为。
- 跨段选择处理（多段落拼接的简化策略：整体生成 vs 按段）。
- 长度度量口径：词数 vs 字符数（以英语 token 界定，给出跨语言建议）。

## Answer

B 票定版：

- **上限与行为**：默认 500 单位（词/字），超限截断为前 500 单位 + toast 提示（含"已讲解前 500 词"）；不做按钮禁用态。
- **归一化 → textHash**：①strip HTML 标签 + 解码实体 → ②Unicode NFKC → ③lowercase → ④非字母数字 → 空格 → ⑤空白折叠/trim → `sha256` 十六进制。**`text` 存归一化前展示版（原样、含换行），`text_hash` 存归一化结果**——展示与键输入分离。
- **长度口径**：空白分词数为主；CJK 类无空格语言退化为字符数（判定：去空白后字符数 / 分词数 > 2），共用常量 500；UI 文案"500 词/字"自适应。
- **跨段与空输入**：多段合并为一条（simple 支持 `\n`，notes 全文顺序）；归一化后为空 → 不调 AI，面板内联"没有可讲解的文本"提示。
- **常量落点**：`src/services/explainer/constants.ts`（`MAX_INPUT_UNITS = 500` + 注释 + HASH_ALGO 说明）；与 04 面板默认展开层常量同为"配置单点"，未来升设置项只需替换常量来源。fog"上限/目标水平设置化"维持。
